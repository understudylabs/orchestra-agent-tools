Proposed next step · Not implemented

Can a cheaper model finish the task correctly?

Evaluate total cost per correctly completed task, including tools, retries and unsuccessful runs.

1 · Establish the overlap

“We already have the model-call evidence.”

We capture prompts, responses, usage and caller-supplied grouping metadata. AUDR overlaps with some of this.

2 · Identify the addition

“You can supply standardized workflow context.”

Executed tools, operation relationships and declared outcomes depend on harness instrumentation. A declared success still needs verification.

3 · Agree on the experiment

“Together, we can test workflow economics.”

Move from “this call costs less” to “this task costs less to complete correctly.” Include extra tools, retries and failures.

The concrete ask for Chargebee

“Let’s take one real run, join its AUDR operations to our captures, and see whether we have enough evidence to evaluate a cheaper model.”

Leave with answers to:

  • Can we reliably connect their operation IDs to our request IDs?
  • Are tools, retries and outcomes fully represented?
  • What does “success” mean, and how will we verify it?

The local join prototype exists. Automatic correlation and evaluation handoff remain to build. No production gateway integration is required for this experiment. Payload capture depends on workload settings; AUDR coverage depends on product-side instrumentation.

Important overlap: Orchestra already records usage and supports session IDs, trace IDs, and customer/feature tags when the caller sends them. AUDR standardizes that context across systems. Its additional value here is explicit harness-side execution and outcome reporting. The product must instrument and supply those facts; AUDR cannot discover them automatically. We can already build task-level evaluations from traces and application context; AUDR can make those workflow facts easier to exchange and join consistently.

What this unlocks

  • Find costly runs and distinguish model expense from executed tool expense.
  • Locate payload evidence for the model calls in those runs.
  • Build an evaluation plan around complete tasks, including failed attempts.

A join is the start of an investigation. It does not establish replay readiness, quality, savings, or complete workflow coverage.

Validate with Chargebee

  1. Export one real harness run with its tools, sub-agents and outcome.
  2. Associate each model operation with the existing x-understudy-request-id response header.
  3. Check parent spans, retries and export-window completeness.
  4. Agree on cost meaning and independently review outcome quality.
  5. Choose a workload, evaluation owner and acceptance criteria.
